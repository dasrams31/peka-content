Chatbot nunggu kamu bertanya, lalu menjawab. AI agent diberi tujuan, lalu kerja sendiri sampai tujuan itu tercapai. Bedanya kelihatan sepele, tapi dampaknya besar: chatbot butuh kamu di setiap langkah, agent bisa menyelesaikan pekerjaan multi-langkah tanpa kamu pegangi.

Contoh konkret. Kamu bilang ke chatbot: "carikan aku 5 artikel terbaru tentang LangGraph". Ia menjawab dengan teks. Kamu bilang ke AI agent hal yang sama: ia membuka pencarian, mengunjungi hasilnya satu per satu, membuang yang tidak relevan, merangkum yang penting, lalu menyerahkan laporan akhir. Ia yang merencanakan langkahnya, bukan kamu.

Tutorial ini menjelaskan apa itu AI agent secara praktis, kenapa 2026 disebut tahunnya agent, dan yang paling penting: kamu akan bikin satu agent nyata dengan Python sebelum selesai baca.

AI agent itu apa, dalam bahasa praktis

AI agent adalah program yang menggabungkan empat komponen. Pertama, model LLM sebagai otak. Ini yang memahami instruksi dan memutuskan langkah berikutnya. Kedua, tools sebagai tangan. Function calling, API, query database, eksekusi kode, pencarian web. Tanpa tools, agent cuma bisa ngomong.

Ketiga, memori atau state. Riwayat percakapan dan hasil tools sebelumnya, supaya agent tidak lupa apa yang sudah dikerjakan. Keempat, loop kontrol. Orkestrator yang menjalankan siklus: berpikir, bertindak, mengamati hasil, lalu mengulang.

Empat komponen itu saja. Tidak ada sihir. Framework seperti LangGraph atau CrewAI pada dasarnya cuma menyediakan cara rapi untuk mengatur keempat komponen ini, plus fitur tambahan seperti human approval dan observability.

Cara kerja: loop think, act, observe

Jantung setiap agent adalah satu loop sederhana: tujuan, berpikir untuk merencanakan langkah, bertindak dengan memanggil tool, mengamati hasilnya, lalu cek apakah sudah cukup. Kalau belum, ulangi.

Misalnya agent riset harga VPS dengan tujuan "bandingkan 3 provider VPS termurah". Pertama, model memutuskan ia butuh data harga, jadi ia akan memanggil tool pencarian web. Kedua, ia memanggil pencarian itu. Ketiga, hasil pencarian masuk ke memori. Model menilai: sudah cukup untuk 3 provider? Belum? Ia panggil lagi dengan query berbeda. Loop berhenti saat model menilai jawabannya sudah lengkap, atau saat batas iterasi tercapai.

Satu hal yang membedakan agent dari skrip biasa: alur langkahnya tidak ditulis manual oleh programmer. Kamu tidak menulis "pertama search A, lalu buka B, lalu rangkum C". Kamu memberi tujuan dan tools, model yang menyusun urutannya sendiri, termasuk memperbaiki diri saat satu langkah gagal.

Kenapa 2026 disebut tahun AI agent

Ini bukan sekadar hype. Tiga hal konkret terjadi tahun ini. Pertama, MCP jadi standar tools. Model Context Protocol adalah cara standar agar agent bisa memanggil tool dan sumber data eksternal. Artinya tool yang kamu tulis sekali bisa dipakai lintas framework, bukan terkunci di satu ekosistem.

Kedua, framework matang. Pilihannya sekarang jelas per kebutuhan: LangGraph untuk workflow kompleks dengan state dan human-in-the-loop, CrewAI untuk tim multi-agent dengan peran seperti researcher dan writer, OpenAI Agents SDK untuk agent tunggal yang sederhana, AutoGen untuk percakapan antar-agent.

Ketiga, adopsi enterprise nyata. Gartner memproyeksikan 40 persen aplikasi enterprise akan memakai task-specific agent pada akhir 2026, naik dari kurang dari 5 persen. Artinya skill membangun agent bukan lagi eksperimen, tapi kebutuhan pasar kerja. Buat kamu sebagai developer Indonesia, bisa bikin agent sederhana adalah pembeda yang konkret di CV dan portfolio tahun ini.

Bikin agen AI pertamamu dengan Python

Kita bikin agent cuaca sederhana. Ia menerima pertanyaan bahasa manusia, memutuskan sendiri kapan perlu memanggil tool cuaca, lalu menjawab dengan data hasil tool. Ini agent beneran, bukan chatbot, karena ia yang memutuskan langkahnya.

Pasang dulu library yang dibutuhkan, lalu buat file agent_cuaca.py. Tool pertamamu cuma satu fungsi yang mengembalikan data dari dictionary. Di produksi, ganti dengan panggilan API nyata seperti OpenWeather atau data BMKG.

import json
from openai import OpenAI

client = OpenAI(api_key="MASUKKAN_API_KEY_KAMU")

def get_weather(city: str) -> str:
    data = {
        "Jakarta": "29 derajat, hujan ringan",
        "Bandung": "24 derajat, berawan",
        "Surabaya": "31 derajat, cerah",
    }
    return data.get(city, "Data cuaca kota tersebut tidak tersedia")

Selanjutnya daftarkan tool itu ke model dalam format function calling, lalu tulis loop-nya. Batas iterasi itu guard wajib: agent tidak boleh loop tanpa henti.

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Ambil cuaca terkini sebuah kota di Indonesia",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "Nama kota, contoh: Jakarta"}
                },
                "required": ["city"],
            },
        },
    }
]

MAX_ITERATIONS = 5

for i in range(MAX_ITERATIONS):
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        tools=tools,
    )
    msg = response.choices[0].message
    messages.append(msg)

    if not msg.tool_calls:
        print("Agent:", msg.content)
        break

    for call in msg.tool_calls:
        args = json.loads(call.function.arguments)
        result = get_weather(args["city"])
        messages.append(
            {
                "role": "tool",
                "tool_call_id": call.id,
                "name": "get_weather",
                "content": result,
            }
        )

Jalankan dengan perintah python agent_cuaca.py. Yang terjadi di balik layar: model membaca pertanyaan dan memutuskan ia butuh data cuaca Bandung. Ia memanggil get_weather("Bandung"), bukan menjawab langsung. Hasil "24 derajat, berawan" masuk ke memori sebagai pesan tool. Model menyimpulkan berawan 24 derajat cukup nyaman untuk lari pagi, lalu menjawab final.

Itu loop think, act, observe dalam 30 baris kode. Semua agent yang lebih canggih, dari LangGraph sampai agent coding seperti Claude Code, pada dasarnya menjalankan pola yang sama dengan tools yang lebih banyak.

Kesalahan umum pemula

Pertama, loop tanpa batas iterasi. Ini kesalahan paling mahal. Agent yang bingung bisa memanggil tool ratusan kali sampai token habis. Selalu pasang MAX_ITERATIONS seperti contoh di atas, dan log setiap iterasi supaya kamu bisa audit.

Kedua, tool tanpa validasi input. Model kadang memanggil tool dengan argumen ngaco, misalnya kota kosong atau format tanggal aneh. Bungkus setiap tool dengan validasi dan nilai default yang aman. Tool yang crash membuat seluruh loop gagal.

Ketiga, system prompt terlalu longgar. "Kamu asisten hebat, bantu user" menghasilkan perilaku tidak konsisten. Tulis system prompt yang spesifik: kapan boleh memanggil tool, kapan harus bertanya balik, dan apa yang dilarang, contohnya jangan mengarang angka.

Keempat, tidak mencatat tool call. Saat agent berperilaku aneh, hal pertama yang kamu butuhkan adalah riwayat: tool apa dipanggil, dengan argumen apa, hasilnya apa. Print atau simpan ke log sejak hari pertama, jangan menunggu ada bug.

Kelima, pakai model mahal untuk semua langkah. Tidak semua langkah butuh model flagship. Klasifikasi intent dan pemanggilan tool sederhana jalan baik dengan model kecil yang sepuluh kali lebih murah. Cadangkan model besar untuk penalaran akhir yang kompleks.

Langkah praktis yang bisa dicoba hari ini

Jalankan contoh di atas sampai berhasil dan pahami setiap iterasi loopnya. Lalu ganti get_weather dengan tool nyata: query ke database SQLite project-mu, atau hit API publik tanpa key seperti Open-Meteo. Tambahkan tool kedua, misalnya send_telegram yang mengirim hasil ke bot Telegram-mu. Sekarang agentmu punya dua tangan.

Coba pertanyaan yang butuh dua langkah: "cuaca Jakarta bagaimana, kirim hasilnya ke Telegram saya". Lihat agent menyusun urutannya sendiri. Kalau sudah nyaman, barulah lirik framework: CrewAI kalau mau multi-agent cepat, LangGraph kalau butuh kontrol alur yang presisi.

Satu agent sederhana yang jalan dan kamu pahami penuh nilainya jauh lebih besar daripada demo framework canggih yang kamu tidak bisa debug. Mulai dari loop 30 baris ini, lalu naik kelas saat kebutuhanmu yang menuntut, bukan karena FOMO.
